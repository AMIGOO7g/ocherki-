# Единая книжная система — отчёт v18

1. **Причина расхождения ПК и мобильного.** Расхождение создавал не viewport, а разные входные ветки: основной конструктор вызывал `OcherkiLayoutPagination.build()` без выбранной композиции, а «Тестовый текст» всегда передавал `composition: "cycle"`. Из-за этого фото переводило Test Mode в прямой composition-flow. Значение `cycle` теперь запускает обычную книжную сборку; масштаб экрана не участвует в композиции.

2. **Flow вокруг цитаты.** Цитатная колонка состоит из трёх последовательно измеряемых DOM-зон: текст над цитатой, физическая полоса цитаты, текст под цитатой. Для левой цитаты порядок источника `left-top → left-bottom → right`; для правой `left → right-top → right-bottom`. Цитата не создаёт `break-column`.

3. **Рукописные вставки.** Используется детерминированная последовательность зон `middle → bottom → top → middle → top → bottom`. Внутри выбранной зоны renderer подбирает фактический фрагмент исходного текста длиной 1–5 слов, повторно измеряет страницу настоящим рукописным шрифтом и переносит фрагмент целиком, если он не помещается.

4. **Полевые заметки.** Цвет — `#666666`, непрозрачность `0.76`. Заметка сдвинута на 28 px внутрь trim, сохраняет направление слева снизу вверх / справа сверху вниз и находится на слое `z-index: 1`; основной текст находится выше на `z-index: 2`.

5. **Фотография CTX после открытия.** Фото открытия сразу заносится в историю использованных индексов. CTX выбирает только другую фотографию этой главы с реальным источником и доступным semantic/focal ROI.

6. **Если фотографии или ROI нет.** CTX не создаётся. Пустые main/detail-контейнеры и заглушки не рендерятся; остаётся разрешённый текстовый сценарий.

7. **Выбор ROI.** Приоритет: явный `detailRoi/ctxRoi/roi`, затем распознанные `faces/regions` по семантическому приоритету (глаза, лицо, руки, архитектурные и пейзажные объекты), затем авторская фокусная точка `focalX/focalY`. Без уверенного источника ROI композиция пропускается.

8. **Увеличение detail crop.** Main и Detail Card используют один и тот же `src`. Card имеет отдельный crop viewport; `object-position`, `transform-origin` и масштаб 1.55–3.6 вычисляются из ROI. Исходное изображение не растягивается: обе копии используют пропорциональный `object-fit: cover`.

9. **DARK FADE 2.2.** Две страницы используют один непрерывный исходник поверх отдельного фона `#10100f`. На `<img>` применяется `mask-image` и `-webkit-mask-image`; H и V имеют фиксированные маски, у S переходная область компактнее. Текст автоматически не добавляется.

10. **Исходные фотографии DARK FADE.** Пиксели, цвет, фильтры и файл не меняются. Fade изменяет только alpha изображения и открывает отдельный тёмный слой.

11. **Общие модули.** Все режимы вызывают `OcherkiLayoutPagination.build()` из `book-renderer/layout-pagination-engine.js`. Физическое деление текста выполняет `OcherkiBookRenderer.paginateText()` / `splitRenderedText()`, а итоговую страницу рисует `OcherkiBookRenderer.renderPage()` из `book-renderer/design-pack-01.js`. ПК и мобильный получают одинаковую `geometrySignature`; меняется только масштаб оболочки.

12. **Оставшееся ограничение проверки.** Автоматические JS/серверные проверки выполнены. Облачный браузер блокирует единственный разрешённый внутренний адрес предпросмотра с `ERR_BLOCKED_BY_CLIENT`, поэтому браузерная визуальная приёмка не отмечается как пройденная. Для ручной проверки в Test Mode добавлен единый сценарий «Приёмка A–O».
