# Stable Base Recovery V20 — отчёт по 32 пунктам

1. Mobile Apply падал до построения: верхняя кнопка вызывала `dialog.close()` у закрытого диалога.
2. Исправление внесено в общий обработчик `applyDraft()` в `test-mode.js`; обе кнопки используют его и ждут `session.apply()`.
3. Ранние разрывы возникали из-за смешения визуального wrap редактора с исходным потоком и прежнего немонотонного измерения отдельных префиксов при justify/hyphenation.
4. Визуальные переносы больше не сериализуются: semantic break создают только Enter/`BR` и реальные блочные границы.
5. Engine получает непрерывный исходный Unicode-текст с сохранёнными пользовательскими абзацами.
6. Единственный движок: `OcherkiLayoutPagination` из `book-renderer/layout-pagination-engine.js`.
7. Единственный renderer/paginator: `OcherkiBookRenderer.renderPage()` / `paginateText()` из `book-renderer/design-pack-01.js`.
8. Изменение цитаты запускает полный `assemble()`; её фактическая DOM-высота заново резервируется, затем повторно раскладываются все три участка колонки.
9. Выход заметки вызывали неограниченная строка и геометрия, не сверенная с фактическим рукописным шрифтом.
10. Теперь заметка получает реальную ширину, browser wrap, измеренную высоту и проверку safe zone; `nowrap` и скрывающее усечение не используются как решение.
11. До выхода за разрешённую область создаётся warning: «Заметка слишком длинная для этой области. Сократите текст.»
12. Handwriting мог отсутствовать на desktop из-за расхождения декоративного прохода; теперь он является объектом общей spread model.
13. Margin notes имели ту же причину; теперь они создаются до viewport-масштабирования и рендерятся обеими оболочками.
14. Desktop/mobile получают одну модель, один template и одни object ID; viewport меняет только масштаб интерфейса.
15. Позиция handwriting выбирается детерминированно по upper/middle/lower зонам и физической доступности, без `Math.random()`.
16. «Эпизод 1» был служебным episode-kicker; CTX branch его не рендерит, что закреплено T16.
17. CTX больше не использует same-photo ROI: resolver, атрибуты ROI, scale и literal-crop удалены из актуального пути.
18. Secondary photo выбирается детерминированно из следующего неиспользованного asset; её ID и source обязаны отличаться от main.
19. Если второй фотографии нет, CTX использует короткий редактируемый handwritten secondary в утверждённом контейнере.
20. Если нет отдельного main после opening и нет материала для secondary, CTX не создаётся; пустых slots/placeholders нет.
21. Opening asset сразу попадает в `usedPhotoIndices/usedPhotoSources`; CTX main выбирается только из отличающихся источников.
22. DARK FADE 2.2 уже существовал как общий component/profile.
23. В обычном ритме он зависел от планирования и мог не встретиться; Test Mode теперь вставляет H/V/S принудительно.
24. Общий branch находится в `design-pack-01.js`, профиль — в `design-pack-01.layout.js`, геометрия — в `design-pack-01.css`.
25. Технология: оригинальный `<img>` + CSS alpha mask + отдельное тёмное поле.
26. Bitmap не меняется: отсутствуют brightness/filter, запечённый gradient и генерированный replacement.
27. H показан с утверждённой геометрией и маской 55% → 82%.
28. V показан без изменения crop/scale/placement и маской 38% → 67%.
29. S показан с единственной коррекцией: компактный fade 44% → 62%.
30. Color test использует три разные исходные фотографии; цвет сохраняется до снижения alpha.
31. Test Mode показывает Opening → CTX → 1–2 text spreads → existing photo → DARK FADE.
32. `spreadId`, `templateId`, `sourceTextHash`, object IDs, geometry и visibleDesktop/visibleMobile подтверждают одну spread model для ПК и телефона.

Проверки: 31 JavaScript-набор и 3 серверных теста. Браузерная визуальная проверка учитывается отдельно и не подменяется статическими контрактами.
